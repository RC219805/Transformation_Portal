# CI Configuration Fix - November 24, 2025

## Issue

The CI workflow was including `test_basicsr_tp.py` in core (non-ML) tests, causing test failures due to torch import conflicts when tests ran in the full suite.

**Symptom:**
```
FAILED tests/test_basicsr_tp.py::TestBasicSRTPImports::test_import_from_archs
ImportError: cannot import name 'nn' from 'torch' (unknown location)
```

**Observation:**
- Tests passed when run in isolation: `pytest tests/test_basicsr_tp.py` ✅
- Tests failed in full suite: `pytest tests/` ❌
- Core tests should not include ML dependencies

## Root Cause

### Test Collection Order Issue

When pytest collects all tests in the suite, some interaction between test files leaves the `torch` module in a broken state (partially imported but incomplete). When `test_basicsr_tp.py` is subsequently collected, it tries to import torch-dependent code and fails.

This is a known pytest behavior with complex import dependencies across test files.

### CI Configuration Gap

The CI workflow was correctly excluding `test_model_training.py` from core tests (line 201 in `.github/workflows/build.yml`) but was missing `test_basicsr_tp.py`, which also requires torch.

**Original configuration:**
```yaml
pytest -v tests/ \
  --ignore=tests/test_model_training.py \
  -k "not (ml or slow)" || pytest_exit=$?
```

## Solution

Updated `.github/workflows/build.yml` to also ignore `test_basicsr_tp.py` in core tests:

**Fixed configuration:**
```yaml
pytest -v tests/ \
  --ignore=tests/test_model_training.py \
  --ignore=tests/test_basicsr_tp.py \
  -k "not (ml or slow)" || pytest_exit=$?
```

This ensures that:
1. Core tests (Python 3.10, 3.12) run without ML dependencies
2. ML tests (Python 3.11) include torch and properly test `test_basicsr_tp.py`
3. No test collection order conflicts

## Recommendations

### For Future Test Files

When adding new test files that require ML dependencies:

1. **Mark with appropriate fixtures:**
   ```python
   @pytest.fixture
   def requires_torch():
       pytest.importorskip("torch")
   ```

2. **Update CI workflow:**
   Add to `--ignore` list in core tests if file has module-level torch imports

3. **Test in isolation first:**
   ```bash
   pytest tests/test_new_ml_feature.py -v
   ```

4. **Verify in full suite:**
   ```bash
   pytest tests/ -v
   ```

### Test Organization Best Practices

Consider organizing tests by dependency:
```
tests/
├── core/           # No ML dependencies
├── ml/             # Requires torch/ML libs
└── integration/    # Full stack tests
```

This would make CI configuration more maintainable:
```yaml
pytest -v tests/core/  # Core tests
pytest -v tests/ml/    # ML tests
```
