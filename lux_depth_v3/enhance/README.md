# V3 + V2 Enhancement Orchestrator

## Overview

The **enhance orchestrator** integrates Depth Anything 3 (DA3) depth estimation with the production-ready V2 enhancement pipeline. This provides a complete end-to-end workflow:

1. **Stage A (V3)**: Generate high-quality depth maps using DA3
2. **Stage B (V2)**: Apply depth-aware enhancement (weights, grading, upscaling, exports)

## Key Features

### Production-Quality Integration
- **No code duplication**: V2 remains the canonical enhancement engine
- **Clean separation**: V3 generates depth, V2 consumes it
- **Full provenance**: Combined manifests link all processing stages
- **Reproducible**: Git hashes, model versions, parameters tracked

### Flexible Execution
- **Resume support**: Skip existing outputs unless `--force-*` flags used
- **Failure policies**: Configure behavior on depth generation failures
- **Device pinning**: Run depth and enhancement on different GPUs
- **Sequential/pipelined**: Choose execution mode based on resources

### Depth Contract Compliance
- **uint16 PNG output**: Matches V2's expected input format
- **Single-channel**: No RGB depth maps (V2 enforces this)
- **Robust quantization**: Percentile-based scaling (p1p99, p0.5p99.5, minmax)
- **Shape validation**: Ensures (H, W) matches input image

## Directory Structure

```
<output_root>/
  depth/                       # Generated by V3
    <stem>_depth.png          # uint16 depth map
    <stem>_depth_manifest.json # Optional per-image metadata
  v2/                          # Produced by V2
    <stem>_master16.tif       # 16-bit master output
    <stem>_upscaled16.tif     # Upscaled 16-bit output
    <stem>_marketing.png      # 8-bit marketing export
    <stem>_preview.jpg        # Preview
    <stem>_report.json        # V2 processing report
  manifests/
    <stem>_combined.json      # Combined V3+V2 manifest
  logs/
    v3_enhance.log            # Orchestrator log
    v2_<stem>.log             # Per-image V2 logs
```

## Command-Line Usage

### Basic Usage

```bash
# Requires license acknowledgement for DA3 (CC-BY-NC)
lux-depth-v3 enhance \
  --input-dir renders/ \
  --output-dir output/ \
  --non-commercial-ok
```

### Production Quality

```bash
# Use production_ultra preset with specific model
lux-depth-v3 enhance \
  --input-dir renders/ \
  --output-dir output/ \
  --model metric-large \
  --v2-preset production_ultra \
  --non-commercial-ok
```

### Resume Previous Run

```bash
# Skip existing depth/V2 outputs
lux-depth-v3 enhance \
  --input-dir renders/ \
  --output-dir output/ \
  --non-commercial-ok
```

### Force Regeneration

```bash
# Force complete regeneration
lux-depth-v3 enhance \
  --input-dir renders/ \
  --output-dir output/ \
  --force-depth \
  --force-v2 \
  --non-commercial-ok
```

### Advanced: Device Pinning

```bash
# Run depth on GPU 0, V2 on GPU 1
lux-depth-v3 enhance \
  --input-dir renders/ \
  --output-dir output/ \
  --depth-device cuda:0 \
  --v2-device cuda:1 \
  --non-commercial-ok
```

## CLI Options

### Required
- `--input-dir, -i`: Input directory with images
- `--non-commercial-ok`: Acknowledge non-commercial use (required for DA3)

### Optional
- `--output-dir, -o`: Root output directory (default: `output`)
- `--model, -m`: DA3 model variant (default: `metric-large`)
- `--v2-preset`: V2 enhancement preset (default: `production_ultra`)
- `--v2-device`: Device for V2 (default: `auto`)
- `--v2-upscaler`: V2 upscaler backend (default: `torch`)
- `--depth-device`: Device for depth (default: `auto`)
- `--depth-quantization`: Quantization method (default: `p1p99`)
- `--execution-mode`: Sequential or pipelined (default: `sequential`)
- `--depth-fallback`: Failure policy (default: `fail`)
- `--force-depth`: Force depth regeneration
- `--force-v2`: Force V2 re-enhancement
- `--v2-timeout`: V2 timeout in seconds (default: 600)
- `--verbose, -v`: Enable verbose logging

## Depth Fallback Policies

### `fail` (default)
Stop processing if depth generation fails. Safest for production.

```bash
lux-depth-v3 enhance ... --depth-fallback fail
```

### `skip`
Skip image if depth fails, continue with others. Useful for batch processing.

```bash
lux-depth-v3 enhance ... --depth-fallback skip
```

### `v2-auto`
If DA3 depth fails, let V2 auto-generate depth (DA2 path). Marks manifest clearly.

```bash
lux-depth-v3 enhance ... --depth-fallback v2-auto
```

## Python API Usage

```python
from pathlib import Path
from lux_depth_v3.enhance import EnhanceOrchestrator, EnhanceConfig
from lux_depth_v3.config import ModelVariant

# Configure
config = EnhanceConfig(
    model_variant=ModelVariant.METRIC_LARGE,
    v2_preset="production_ultra",
    non_commercial_ok=True,
    depth_fallback="skip",
)

# Initialize orchestrator
orchestrator = EnhanceOrchestrator(config, Path("output"))

# Process batch
results = orchestrator.enhance_batch(Path("renders"))

# Examine results
for result in results:
    if result["status"] == "ok":
        print(f"✓ {result['image']}")
        print(f"  Depth: {result['depth_path']}")
        print(f"  Report: {result['v2_report']}")
        print(f"  Manifest: {result['manifest']}")
    elif result["status"] == "error":
        print(f"✗ {result['image']}: {result['error']}")
```

## Depth Writer Contract

The depth writer ensures V2 contract compliance:

```python
from lux_depth_v3.enhance import write_depth_u16_png
import numpy as np

# Generate depth (float32 or uint16)
depth = np.random.rand(1024, 1024).astype(np.float32)

# Write with quantization
p1, p99 = write_depth_u16_png(
    Path("depth/image_depth.png"),
    depth,
    method="p1p99",
    debug_verify=True,  # Optional verification
)

print(f"Quantized: p1={p1:.3f}, p99={p99:.3f}")
```

### Rules
1. **Output format**: uint16 PNG, single channel
2. **Naming**: `{stem}_depth.png`
3. **Shape**: Exactly (H, W) matching input
4. **Quantization**: Robust percentile-based scaling
5. **Validation**: Optional debug mode verifies read-back

## Troubleshooting

### License Error
```
ERROR: DA3 models require license acknowledgement.
For non-commercial use, add: --non-commercial-ok
```

**Solution**: Add `--non-commercial-ok` flag to acknowledge CC-BY-NC license.

### V2 Not Found
```
V2RunnerError: Cannot find lux_depth_v2 module.
```

**Solution**: Ensure `lux_depth_v2` is installed or in PYTHONPATH.

### Depth Generation Timeout
```
Depth generation failed: timeout
```

**Solution**: 
- Check GPU availability
- Reduce image resolution
- Use faster model variant (`base` instead of `giant`)

### V2 Enhancement Fails
```
V2 failed with exit code 1
```

**Solution**: Check V2 logs in `logs/v2_<stem>.log` for details.

### Resume Not Working
```
Depth exists, but still regenerating
```

**Solution**: Remove `--force-depth` flag to enable resume.

## Best Practices

### Production Deployment
1. Use `--depth-fallback skip` for batch robustness
2. Set reasonable `--v2-timeout` (e.g., 600s)
3. Monitor `manifests/` for processing status
4. Review failed images in summary

### Development/Testing
1. Use `--verbose` for detailed logging
2. Process small batches first
3. Verify depth quality before V2 enhancement
4. Check manifests for timing bottlenecks

### Performance Optimization
1. Use `metric-large` instead of `giant` for 2-3x speedup
2. Pin devices if multiple GPUs available
3. Enable resume to avoid reprocessing
4. Consider pipelined mode for multi-GPU setups

## Limitations

### Current Version
- **Sequential mode only**: Pipelined mode planned for future
- **Single-image V2**: V2 processes one image at a time
- **No batch depth**: DA3 processes images individually

### Known Issues
- V2 timeout may need adjustment for large images (>4K)
- Resume detection relies on file existence (no hash verification)
